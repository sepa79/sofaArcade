# War for Crown C64 Port Completeness Matrix

This is the tracking matrix for the `c64-original-simple` port. It indexes the
recovered C64 behavior and the evidence used by the automated parity gate.

Recovered-but-unmodeled RAM fields are tracked in
`c64-active-state-gap-audit.md`.

Status legend:

| Status | Meaning |
| --- | --- |
| Recovered | Address-backed behavior is known well enough to implement. |
| Fixture Needed | Behavior is known, but byte-level tests are still required. |
| Partial | Entry point and broad behavior are known, but exact branches/UI text remain open. |
| Open | Exact C64 behavior is not recovered yet. |

## Automated Runtime Parity Gate

`pnpm --filter war-for-crown test:parity` compares the selected `ERBENT1A`
modules running in VICE with the TypeScript port under the same deterministic
RNG byte stream. The gate currently proves:

1. all 26 simple-mode random-event modules;
2. 14 seed/configuration cases for map, home selection, initial state, AI
   phases, battle, royalist production/distribution, and hostile variants;
3. three scripted human-incursion states (weak, strong, and fortified) with a
   real human player slot, comparing the following AI player's new-month,
   attack, movement, and economy reactions;
4. seed `15`, where both implementations reach winner `p2` after 17 completed
   rounds;
5. seed `11` through 38 rounds, covering more than three in-game years without
   turning the gate into a long AI-versus-AI soak test.
6. a seed `11` 12-round behavioral gate that fails unless attacks, combat,
   captures, royalist defender retreats, recruitment, soldier distribution,
   village purchases, fortification upgrades, and income all occur.

Snapshots compare owners, fortifications, villages, 24-bit soldiers and money,
AI memory, ranks, royalist buckets, calendar/weather, reinforcement timing, and
the exact number of consumed RNG bytes. A newly found C64 counterexample must
be added as a focused unit vector or a bounded parity scenario.

## Remaining Boundaries

- `$CA55/$CA56` supplies, catapults, and other full-rules behavior are
  intentionally outside `c64-original-simple`.
- Complete PL/EN reproduction of C64 text is presentation/localization work,
  not a gameplay-logic parity blocker.
- The deterministic harness supplies identical RNG bytes to both sides; it does
  not attempt to reproduce physical VIC-II raster timing.
